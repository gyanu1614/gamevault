## Notice start date (step 4) — no rule changed
PR 4 (`20260922001513`) computes `v_start := GREATEST('2026-10-06 00:00Z', date_trunc('day', (now() + notice_days) AT TIME ZONE 'UTC') + interval '1 day')` — **the first 00:00 UTC strictly after now() + 14 days, on the day the migration actually runs**; PR 4's "7 Oct" assumed a 22 Sep UTC push. Pushed 23 Sep UTC → 8 Oct; the local re-seed on 24 Sep UTC produced **9 Oct** (`select min(starts_at) from fee_rules where note like 'PR4:%'`). Correction to my previous handoff: I never queried prod — the 8 Oct figure came from the local stack; prod's value is whatever `min(starts_at)` says there. Not a timezone artefact of the DB (the column is `timestamptz`, midnight UTC), but a **browser/Node local-time render** would show the previous day west of Greenwich (`2026-10-08T00:00Z` → "7 October" in PDT). Fix: one `formatScheduleDateUtc()` (en-GB long form, `timeZone: 'UTC'`) used by `/sell/fees` and the notice email, pinned by `schedule-date.test.ts`; the notice reads the date from `fee_rules` at send time.
